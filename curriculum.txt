Every stage is a **fresh WandB run and a fresh checkpoint lineage**. 
Weights transfer across stages with - 
    ./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/train.py \
    --task Isaac-Velocity-Kick-H1-v0 \
    --num_envs 4096 \
    --headless \
    --logger wandb \
    --resume \
    --load_run <run_folder> \
    --checkpoint <model.pt>

## Stage 1 — Learning to Swing the Leg

**Environment:**
- Ball spawned at `(0, 0, 3.0)` m — 3 m above the robot, directly overhead and
  physically unreachable. Present in the observation vector (deliberately,
  to avoid an observation-space change later) but involved in no contact.
- No ball-constraint event active — nothing to constrain yet.
- `episode_length_s = 25.0`, `decimation = 4`, `sim.dt = 0.005` (all constant
  for the rest of the project).
- Objective: pure single-support balance plus the shaped, physically-derived
  two-phase kicking-swing trajectory (`foot_swing_knee_extend`, weight 4.0) —

## Stage 3.1 — Keeping the Ball Aloft (Z constraint removed)

  `pin_y=True` remain — only vertical motion is free.

## Superseded designs (kept for the record)

- **Reduced-gravity "balloon ball" ladder.** A five-rung schedule scaling
  effective gravity (`g_eff = k·9.81`, `k ∈ {0.14 … 1.0}`) was fully designed
  and debugged for Stage 3 — including fixing a frame bug where the
  compensating force was applied in the ball's local frame and post-kick spin
  bent "up" sideways. It was superseded by the simpler rail-release sequence
  above, which reached full gravity without intermediate physics rungs. The
  helper (`ball_gravity_scale`) remains in `kick_events.py`, unused.
- **Auto-gated 7-stage curriculum.** An earlier design advanced stages
  automatically on rolling success rates. Replaced by manual, per-stage config
  edits + fresh runs: with reward surfaces changing between stages, automatic
  advancement mid-run would have resumed optimizer state across surface
  changes — exactly the failure mode the fresh-lineage rule exists to prevent.
  The dead module (`kick_curriculums.py`) has been deleted; it's in git history.

## Next rungs (designed, not yet trained)

- **3.4 — spatial generalization.** Randomize `distance_offset` ∈ [0.55, 0.75]
  and **signed** `lateral_offset` ∈ [−0.085, +0.085] in `reset_ball_state`, so
  the ball lands on the robot's left half the time. Leg choice then falls out
  of spawn geometry for free — no reward-side alternation mask needed — and
  the run doubles as the memorization-vs-generalization test.
- **3.5 — alternation.** Only after 3.4 holds: `alternate_foot_bonus`
  (already wired, weight 0.0) turned on small (~5.0 vs. contact's 120.0) to
  nudge alternation without making single-foot play unrewarding.
- **3.6 — hardware-facing regularization**, as an isolated run before DR:
  `joint_torques_l2`, `dof_acc_l2`, raised `action_rate_l2`, and a base
  position tether (currently only *velocity* drift is penalized).
- **Stage 4 — domain randomization**, in order: ball mass ±15% / restitution /
  ground friction → actuator stiffness/damping → observation noise
  (`enable_corruption=True`, excluding `swing_phase`) + action-delay queue →
  base pushes.
